# Security and operations notes

This page covers dependency pinning, failure notification, secret rotation,
supply-chain rules, runtime requirements and incident steps. Checked offline by
`py -3.14 scripts/check_s10_4.py`.

## Dependency policy

- Ranges live in `pyproject.toml` (`dependencies` and `[project.optional-dependencies].dev`).
  Do not pin them there.
- Exact pins live in `requirements/lock.txt`, generated by uv for both Ubuntu CI and Windows:

  ```bash
  uv pip compile pyproject.toml --extra dev --universal --python-version 3.11 -o requirements/lock.txt
  ```

- Workflows install with the lock as a constraint:
  `python -m pip install -c requirements/lock.txt -e ".[dev]"`.
- Dependabot opens weekly (Monday 09:00 UTC) pip and GitHub Actions update PRs in
  `.github/dependabot.yml`. Minor and patch updates are grouped into one PR per ecosystem.
- When a Dependabot PR changes `pyproject.toml` or `requirements/lock.txt`, regenerate the
  lock on that branch with the command above, then run the verification below before merging.
- Verify the lock: `py -3.14 scripts/check_s10_4.py`, then in a scratch venv
  (`uv venv scratch/s10_4_venv`) run `uv pip install -c requirements/lock.txt -e ".[dev]"`
  and `python -m pytest -q tests/test_s10_4.py`.

## Failure notification

- Scheduled workflows on the default branch (`ingest_works`, `build_deploy`, `watchdog`,
  `keepalive`, `source_watch_s7_6`) send GitHub's built-in Actions failure email.
- GitHub addresses that email to the repository owner or to the user who last changed the
  workflow's cron schedule. Confirm delivery in GitHub under Settings → Notifications → Actions
  (leave Actions notifications enabled, with failed-workflow emails on), and confirm the account that
  receives it is one you check.
- `watchdog.yml` is a second channel, not an alert. Once a day it checks the last
  `build_deploy.yml` run and re-dispatches it on the default branch when that run is
  older than 25 hours or missing. A failed run does not page anyone by itself.
- If a scheduled run fails and no email arrives, open the run in the Actions tab, then open an issue.

## Secret rotation

Runbook for `OPENALEX_API_KEY`:

1. Create a new key at the OpenAlex provider. Do not revoke the old key yet.
2. Set the Actions secret from a terminal prompt so the value never appears on the
   command line or in shell history:
   `gh secret set OPENALEX_API_KEY` (paste the value at the prompt).
3. Verify with a manual run of `ingest_works`:
   `gh workflow run ingest_works.yml --ref main`, then `gh run watch`.
4. Verify a budget-deferred smoke run: set `OPENALEX_MAX_CREDITS` low for one manual run
   so the job defers cleanly instead of spending credits, and confirm the run succeeds.
5. Update the local `.env` by hand with the new value. Do not paste it into chat, issues or logs.
6. Revoke the old key at the provider once steps 3-5 pass.

Never echo a secret value in logs, workflow summaries, commits or issues. Mask it if a
script must print a value's presence.

Generic template for any future secret:

1. Name: `<SECRET_NAME>`. Owner: `<who holds the provider account>`. Used by: `<workflow or script>`.
2. Create the replacement at the provider; keep the old value active until verification passes.
3. Set it with `gh secret set <SECRET_NAME>` at the prompt. Record the date in the table in
   `docs/SECRETS.md` (the name only, never the value).
4. Verify with a manual `workflow_dispatch` of each workflow that reads it.
5. Update local `.env` by hand, then revoke the old value at the provider.

## Supply-chain notes

- GitHub Actions are pinned to major version tags (for example `actions/checkout@v7`).
  Dependabot's github-actions ecosystem proposes updates.
- Libraries loaded from a CDN in spikes are pinned to exact versions, not ranges.
- No secrets in client code. The static site (`site/`) must not contain API keys,
  tokens or `.env` values.
- `ENABLE_DATA_COMMITS` must be exactly `true` for workflows to commit generated data.

## Runtime requirements

- Python: 3.11 or newer. CI runs 3.11; local development uses `py -3.14`.
- Node.js 20 or newer is needed by the S7.5 runtime tests.
- Dependencies are resolved from PyPI only. No other package index is configured.

## Incident response

1. Set repository variable `ENABLE_DATA_COMMITS` to `false` (`gh variable set ENABLE_DATA_COMMITS --body false`)
   so no workflow commits generated data.
2. Revoke any exposed key at its provider, then rotate it using the runbook above.
3. Disable a workflow if it is still running unsafely (`gh workflow disable <file>`).
4. Open an issue describing the time, workflow run URL, affected secret or data,
   and actions taken. Do not include secret values.
5. Re-enable the workflow and `ENABLE_DATA_COMMITS` only after the cause is fixed.
