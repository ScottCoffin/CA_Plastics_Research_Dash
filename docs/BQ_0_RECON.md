## Consequences for BQ tasks

- **BQ-S9 (rows 2-5).**
  - The join key is not stored. Either take `ids.pmid` from OpenAlex (a field that stored data does not carry; a fetch is needed) or use DOI with PubMed article identifiers, which the spec names as the fallback. The join-rate report must say which key was used.
  - PubMed retrieval cap: 10,000 for `retstart + retmax`. The bisection threshold must sit below 10,000 minus the configurable margin. A single day still over the cap must fail loudly, as the spec says. Paging past 10,000 is not available for PubMed.
  - Rate limit: the default should be 3 requests per second without a key and 10 with one. `tool` and `email` must be registered with NCBI for the request to be compliant. Registration is an owner action and is not done here.
  - The PubMed count moves daily (whole-database count 41,456,390 on 2026/11/18 06:25 in row 5). Every run's manifest must carry its run date.
- **BQ-1.x (row 6).** Use `primary_topic.id:T10753`, which is the repo's own topic field, for the topic recall probe. Keep `topics.id` out until a count-only check, if the task authorizes one, confirms the filter. The display name and `works_count` (93,500) match the spec.
- **BQ-2.1 (row 7).** Series C uses `ca_any_author` (work level). Use `ca_led` only when a first-author cut is needed. Document that the flag includes the `author_carry_forward` and `escholarship` bases, and report their shares. Add `ca_basis` to the data dictionary (BQ-2.1 or BQ-9 docs), and correct the `ca_any_author` wording.
- **Row 1 (no BQ data task).** Section 1 of the spec should describe the repo's global root. BQ-R1 conflicts with the repo: A3-C4 (resolved 2026-11-18) says BQ-R1 adds redirect stubs for renamed routes, while ADR-PLAT1-LAYOUT-2026-11-17 says no redirect stubs (owner, clean break). The owner must decide before BQ-R1 runs. The live site should be checked after the next deploy.
